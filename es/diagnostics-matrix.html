Matriz de diagnóstico de modos de fallo y guía de triaje entre aplicaciones

Empieza por la capa del fallo observado, no por una causa supuesta. Estos nueve modos de fallo y tres recetas de triaje con dos destinos amplían los casos de estudio existentes; no añaden funciones al motor ni garantías de producción.

Una ruta de triaje acotada

  1. Si el navegador no puede leer una respuesta o adjuntar una cookie, separa primero el acceso a la respuesta mediante CORS de la elegibilidad de la cookie. Una respuesta bloqueada no demuestra que el servidor no actuara.
  2. Para una captura SSE/NDJSON guardada y autorizada, revisa tramas del protocolo, señales de terminación, JSON de argumentos y marcas de tiempo disponibles. No deduzcas tiempos ausentes ni corrección semántica.
  3. Si hay reintentos, pérdida de respuestas o finalización desconocida de una modificación, concilia el estado del servidor antes de repetir y modela identidad estable de la intención, retención y presupuestos de reintentos anidados.

Triaje entre aplicaciones

Flujo → reintentos o políticas del navegador

Cuándo continuar: Una captura está incompleta, duplicada o no es accesible para el navegador.

Transferencia manual: Comparte solo nombre del adaptador, número de eventos, estado terminal, códigos de resultados estructurales y disponibilidad de tiempos; omite eventos y argumentos de herramientas.

Continuación: Para finalización ambigua o intención duplicada, revisa la seguridad de reintentos. Para acceso a respuestas o síntomas de cookies, revisa las políticas del navegador.

Detención / límites: No repitas una modificación para reparar una captura. Una respuesta reconstruida no demuestra corrección semántica.

Agent Retry Safety Lab · CORS & Cookie Doctor

Reintentos → flujo o políticas del navegador

Cuándo continuar: Un tiempo de espera, efecto duplicado o pérdida de respuesta deja incierto el resultado del cliente.

Transferencia manual: Usa una etiqueta sintética de intención, presupuestos/TTL configurados y recuentos modelados de intentos/efectos; nunca copies claves ni cargas útiles reales.

Continuación: Revisa las tramas de una captura guardada y autorizada, o las políticas del navegador si el acceso pudo ocultar una solicitud completada.

Detención / límites: Concilia por separado el estado real del servidor. La simulación no garantiza ejecución exactamente una vez ni prueba contratos del proveedor.

LLM Stream Inspector · CORS & Cookie Doctor

Políticas del navegador → reintentos o flujo

Cuándo continuar: JavaScript no puede leer una respuesta, o la elegibilidad de cookies difiere del acceso CORS.

Transferencia manual: Comparte relaciones de origen/sitio sintéticas o depuradas, método, modo de credenciales, resultados de políticas y si se conoce el envío/finalización; sin tokens ni valores de cookies.

Continuación: Si la solicitud pudo ejecutarse, revisa la seguridad de reintentos antes de repetir. Una vez entendido el acceso, revisa un flujo guardado y depurado.

Detención / límites: La herramienta sin conexión no envía solicitudes ni establece cookies. Confirma el comportamiento real solo en DevTools autorizado; una respuesta bloqueada puede ocultar éxito.

LLM Stream Inspector · Agent Retry Safety Lab

Evidencia depurada y límites de datos

  • Prefiere los ejemplos sintéticos integrados. Obtén autorización antes de usar capturas o cabeceras reales.
  • Elimina manualmente instrucciones, cuerpos de respuesta, argumentos de herramientas, valores Authorization/Cookie/Set-Cookie, identificadores y claves reales de idempotencia. La depuración no es automática.
  • Registra capa de origen, finalización conocida o desconocida, procedencia de tiempos, códigos de resultados y siguiente pregunta. Etiqueta como sintéticos los recuentos del modelo.
  • Los enlaces abren herramientas locales independientes. Ningún dato de diagnóstico se incluye en una URL, se transfiere automáticamente, se sube ni se sincroniza.

Lo que esta guía no demuestra

Son ayudas de diagnóstico sin conexión, no sondeos en vivo, pruebas de conformidad del navegador, certificados de seguridad, evaluadores semánticos ni garantías de ejecución exactamente una vez. La documentación del directorio tiene cobertura completa EN/ES/PT; las interfaces satélite siguen solo en inglés. La verificación estática/HTTPS es una observación fechada, no una auditoría de accesibilidad renderizada ni un SLA.
