Architecture decisions

  • Directory: Zion AI Apps Hub maintains localized discovery and documentation; it does not execute the satellites.
  • Stream diagnostics: LLM Stream Inspector reconstructs saved SSE/NDJSON and inspects framing and tool-call JSON; it does not run inference or prove semantic correctness.
  • Retry diagnostics: Agent Retry Safety Lab models layered retries, response loss, duplicate effects, and key retention; it does not execute mutations or guarantee exactly-once behavior.
  • Browser-policy diagnostics: CORS & Cookie Doctor separates response access from cookie eligibility using supplied context; it does not probe endpoints or certify browser conformance.

Decisions and trade-offs

Each repository publishes independently through GitHub Pages using local assets. No common backend, shared hosted script, model API, login, telemetry, or runtime dependency is introduced. Independent releases reduce coupling but require deliberate content and link checks to prevent drift.

The four-node navigation graph has 12 directed edges, not 12 products: hub to three satellites, and each satellite to the hub and both siblings. Ordinary HTTPS links never carry captures, prompts, headers, cookies, secrets, or scenario inputs. No third-party repository, catalog, DNS, or Pages setting is changed.

Network roadmap

Reconciled status: all six candidates below remain proposals, not launched apps. They come from the existing November 14 roadmap. This batch creates no candidate repository, launch card, registration, or commitment to deliver six products.

  1. Structured Output Portability Checker: compare a supplied JSON Schema against dated provider profiles and report keyword/reference/nullable compatibility with provenance. Not general contract validation or live inference; unknown support stays unknown.
  2. Citation Span Verifier: compare supplied quotes/offsets with local text revisions using explicit Unicode/newline normalization and source hashes. Not retrieval or entailment scoring; a matching quotation does not establish truth.
  3. Conversation Portability Inspector: inspect saved, non-streaming message histories for role and tool-result mapping losses between dated adapters. Not SSE inspection, a chatbot, or a model router; equivalent model behavior is not promised.
  4. Webhook Signature Fixture Lab: verify synthetic payload bytes and test-only HMAC signatures against an explicit timestamp tolerance. Not a live receiver, delivery manager, production-secret store, or durable replay defense.
  5. CSP Policy Explainer: explain supplied policies, directive fallbacks, intersections, and hypothetical resource decisions without loading resources. Not CORS diagnosis or a security score; dynamic cases remain conditional, and blanket unsafe bypasses are not recommended.
  6. Cron & DST Previewer: preview a bounded five-field cron schedule in an IANA time zone and disclose gap/repeat semantics. Not job execution, monitoring, or booking; results depend on the supported dialect and time-zone database.

Next release gates

  1. Choose a narrow scope and review overlap before proposing any new repository; an existing implementation should be extended or linked rather than duplicated.
  2. Obtain separate approval for creation/publication. Keep local processing, bounded computation, explicit unknowns, sanitized fixtures, and clear non-goals.
  3. For a future functional release, test engines and obtain separately scoped rendered/browser QA where appropriate. This content batch does not claim that QA.
  4. Publish only after acceptance, verify HTTPS and exact deployed sources, then add reciprocal links and a dated checkpoint.

Release and continuation

For this batch, acceptance uses bounded static/Node checks, certificate-validated HTTPS GETs, HTTP 200 responses, and deployed-byte hashes against pinned commits. Heavy headless Chromium, rendered mobile/keyboard tests, and live UI interaction checks are intentionally skipped, not reported as passed.

Dated release report and verification links (English). Record the batch ID, parent checkpoint, repository commits, expected/observed results, UTC time, QA limits, blockers, and next action. Never include credentials or diagnostic inputs in checkpoints.

Each utility remains an offline diagnostic aid, not a security certificate or an exactly-once guarantee. Review exports before sharing and confirm real integrations only in an authorized environment.
